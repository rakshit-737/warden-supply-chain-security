A different security question

A clean vulnerability report does not mean a package is safe.

Malicious publishes, typosquats, dependency confusion and account takeovers can arrive without a CVE. Warden keeps behavioural evidence, vulnerability intelligence and provenance visible as separate signals so a verdict is explainable.

Security coverage

Four lenses on dependency risk.

Warden groups its analyzers around decisions engineers actually make: what can this software do, who published it, what is known about it and what should the pipeline permit?

The analysis boundary

A pipeline built for hostile input.

The package is untrusted from the moment it arrives. Warden bounds acquisition and extraction, runs analyzers in parallel, then makes the verdict explainable.

No package code execution
STAGE 01 / ACQUISITION

Acquire the exact release requested.

Warden resolves a concrete (ecosystem, name, version), selects the distribution, applies size and redirect controls, and verifies the registry-published digest against the received bytes.

✓ HTTPS-only hardened client✓ Redirect host allowlist on every hop✓ No fallback to an unrequested “latest” version

Risk engine

One score, many reasons.

The 0–100 risk score is derived from separate dimensions. Vulnerability intelligence that is unavailable is represented as null, never silently converted to zero.

Rules lead. ML stays bounded.

Deterministic evidence can floor a critical score. The ML model may sharpen a rule-supported verdict, but it cannot invent a critical decision when the rules see little.

PEP 503 GATEWAY

Put enforcement in front of pip or uv.

The proxy can audit or enforce policy before a wheel or source distribution reaches the installer. In enforce mode, blocked packages receive HTTP 403.

Proxy architecture ↗
